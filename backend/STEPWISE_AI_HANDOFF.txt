-------------------------------
Name: StepWise — An Interactive Local Socratic Tutoring System Powered by
Large Language Models.

Project guide: Dr. Madhuri Kagale R, Assistant Professor, Department of

Purpose: a local-first tutoring application. A learner asks a question and a
locally hosted Ollama model is prompted to guide the learner with hints and
focused questions instead of immediately supplying a complete solution. The
project is intended as an academic demonstration/research prototype. Socratic
behavior depends on the model and is not guaranteed to be perfect for every
prompt.

The project's academic context includes research comparing Socratic
questioning with direct-answer commercial models (including work cited by the
student such as Friedman et al. and Fakour & Imani, 2025). Ask the student for
their bibliography/source files before inventing formal citations.

3. TECHNOLOGY AND ARCHITECTURE
------------------------------
Frontend:
  - React 19 + Vite, JavaScript/JSX, CSS.
  - Axios/fetch API calls.
  - React Markdown, GFM, remark-math, KaTeX.
  - PDF.js extracts selectable text in the browser.
  - Browser Web Speech API provides speech-to-text when available.

Backend:
  - Python FastAPI, Pydantic validation, SQLAlchemy ORM, SQLite.
  - JWT-based auth; password hashing via Passlib.
  - Ollama Python client calls the configured local model (default
    STEPWISE_OLLAMA_MODEL=gemma4:e2b).
  - POST /api/chat/stream returns Server-Sent Events (SSE) for token streaming.
  - WebSockets power temporary peer rooms.

Data path:
  Browser (React/Vite) <-> FastAPI <-> SQLAlchemy <-> SQLite
                                  |
                                  +---- Ollama local service/model

The app does not use a hosted LLM API for tutor inference. It requires Ollama
and the configured model to be installed/running for live tutor generation.
SQLite defaults to backend/stepwise.db (local development storage).


4. IMPLEMENTED FEATURES IN THE CURRENT CODEBASE
-----------------------------------------------
Core student experience:
  - Landing/welcome page with a dark, animated/orbit-style visual design and
    an interactive sample tutor preview. Logged-in users can continue to the
    studio; logged-out users can open authentication.
  - Student registration/sign-in and current-user profile.
  - Password reset flow. SMTP enables email delivery. For local loopback use,
    a reset link can be returned without SMTP; remote reset requires SMTP.
  - Chat creation, listing, opening, and deletion (owner-only backend check,
    with confirmation in the UI).
  - Subject selection and optional faculty syllabus context.
  - Current subject choices are Algorithms, LAW, Biology, DBMS, and Mathematics.
    Existing chats using the prior label "Constitution of India" remain readable
    and are treated as LAW for tutor scope. Clear cross-subject prompts are
    conservatively detected and redirected before local inference; generic or
    ambiguous wording may not be classified perfectly.
  - Socratic local-model response generation, both normal and streamed.
  - Streaming sends chunks to the frontend and persists the final assistant
    message.
  - Conversation branching: messages have a self-referential
    parent_message_id. Editing a prior student message creates another path
    while retaining the old branch.
  - Adaptive learner-support/frustration tracking, including repeated stuck
    prompts, with escalating guidance in learning_support.py and ai_engine.py.
  - Prompt hardening: conversation messages are treated as untrusted history;
    the tutor system instructions are reasserted to resist requests to abandon
    Socratic behavior or disclose full answers.
  - Markdown/math rendering, code formatting/highlighting and copy controls.
  - Browser voice input (speech-to-text), subject to browser/microphone
    support.
  - Text/code and PDF attachments. Browser extracts attachment text and adds
    it to the chat prompt; there is no independent upload store.
  - Learning Insights: misconception classification/logging plus friendly
    phrases, frequency labels and next-step advice instead of raw technical
    labels/percentages.
  - Peer Blindspot Rooms: temporary, two-participant WebSocket rooms with
    anonymous learner aliases, shared code/chat and local LLM facilitator
    prompts. Room data is in memory and expires; it is not durable/persisted.
  - Faculty syllabus mappings for subject/module/chapter/persona context.
  - Demo data seeder (`backend/seed_demo_data.py`) for sample chats and
    misconception patterns (inspect script before running against any real DB).

User-interface updates already requested in this conversation:

5. CURRENT DATABASE MODEL (backend/models.py)
---------------------------------------------
User:
  id, email (unique), full_name, hashed_password, role, is_active, created_at.
  Owns conversations, syllabus mappings and misconception logs.

Conversation:
  id, user_id FK, title, subject, frustration_score, consecutive_loops,
  created_at, updated_at. Owns messages and misconception logs.

Message:
  id, conversation_id FK, parent_message_id self-FK nullable, role, content,
  created_at. Parent-child relation represents alternative conversation paths.

SyllabusMapping:
  id, user_id FK, subject, module, chapter, persona, created_at.

MisconceptionLog:
  id, user_id FK, conversation_id FK, source_message_id nullable FK,
  category_code, confidence, is_sample, created_at.

Database initialization/migrations are in backend/database.py. It creates the
tables and includes lightweight SQLite column migrations for older databases.

9. SETUP AND RUNNING LOCALLY (WINDOWS POWERSHELL)
-------------------------------------------------
Prerequisites: Python 3.10+, Node.js version compatible with Vite (README
currently lists Node 20.19+ or 22.12+), Ollama, and the configured model.

One-time backend setup, from project root:
  cd backend
  py -3 -m venv .venv
  .\.venv\Scripts\python.exe -m pip install -r requirements.txt
  Copy-Item .env.example .env

Set a private random STEPWISE_SECRET_KEY in backend/.env. A development key
must not be used in production. Optional settings include database URL, model,
CORS origins, SMTP configuration, and faculty invite code.

Ensure Ollama is running and model exists:
  ollama pull gemma4:e2b
If Ollama is not installed as a background service, run `ollama serve` in a
separate terminal. A different locally installed model can be set in
STEPWISE_OLLAMA_MODEL.

Start backend in one terminal (from backend folder):
  .\.venv\Scripts\uvicorn.exe main:app --reload --host 127.0.0.1 --port 8000

Start frontend in a second terminal (from frontend folder):
  npm ci
  npm run dev

Open the URL Vite prints, usually http://127.0.0.1:5173 or
http://localhost:5173. Use the exact port printed in the frontend terminal;
Vite may choose a different port if 5173 is busy. Backend API docs:
http://127.0.0.1:8000/docs.

If a backend port bind error such as WinError 10013 occurs, first check if a
backend process is already listening. Do not launch duplicate Uvicorn servers
on the same host/port. Stop the server with Ctrl+C in its running terminal.
Previously observed local backend listener was PID 2200 on 127.0.0.1:8000;
this is historical and may not be running now.
